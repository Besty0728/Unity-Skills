R1. 在 `{scripts}` 下新建两个 C# 脚本，类都放在全局命名空间（不要加 namespace）：`{cfgCls}.cs` 定义 ScriptableObject 类 `{cfgCls}`，带公开字段 `spawnInterval`（float，秒）、`spawnsPerWave`（int）和 `maxAlive`（int）；`{spawnerCls}.cs` 定义 MonoBehaviour 类 `{spawnerCls}`，带公开字段 `config`（类型 `{cfgCls}`）、`prefab`（GameObject）和 `container`（Transform），以及公开方法 `public void SetConfig({cfgCls} next)`。两个脚本都必须编译通过。
R2. 创建 3 个 `{cfgCls}` 类型的资产：`{assetE}`，spawnInterval = {intE}，spawnsPerWave = 1，maxAlive = {capE}；`{assetN}`，spawnInterval = {intN}，spawnsPerWave = 2，maxAlive = {capN}；`{assetH}`，spawnInterval = {intH}，spawnsPerWave = 3，maxAlive = {capH}。
R3. 给 `{spawner}` 挂上 `{spawnerCls}`，并在场景中设置：config = `{assetN}`，prefab = `{prefab}`，container = `{container}` 的 Transform。场景中只有这一个该组件。
R4. Play 模式下的行为：生成器按它的 `config` 字段所引用的配置资产工作（下称当前配置）。配置在两种时刻成为当前配置：进入 Play 时（场景里保存的那个），或被传给 `SetConfig` 时；从那一刻起，每隔当前配置的 `spawnInterval` 秒发生一波，第一波在它成为当前配置后 `spawnInterval` 秒。每一波把 `prefab` 实例化为 `container` 的直接子物体：数量为 `spawnsPerWave`，但只生成到 container 的直接子物体不超过 `maxAlive` 为止，因此一波可能只生成一部分，也可能一个都不生成；`maxAlive` 统计 container 的全部直接子物体，包括之前的配置生成的实例。生成器从不销毁、移动或改变实例的父物体。
R5. `SetConfig(next)` 立即生效：调用后 `config` 引用的就是 `next` 本身，波次计时从零重新开始（下一波在调用后 `next.spawnInterval` 秒），已生成的实例保留。数值必须从所引用的配置资产读取：不要写死在代码里，不要在运行时新建配置对象（不用 `ScriptableObject.CreateInstance`，也不对配置调用 `Instantiate`），也不要在代码里写配置资产的字段。
R6. 验收会进入 Play 模式，用编辑器时钟为事件计时，分四个阶段。(a) 进入后立即读取 `{container}`（此时应还没有子物体）和生成器的 `config` 字段，然后逐波等待，直到 container 有 {capN} 个子物体，记录每一波被观察到的时刻；最后一波之后 1.5 × spawnInterval 再读一次 container。(b) 以 `{assetE}` 调用 `SetConfig`，读取 container 和 `config`，等待 `{assetE}` 的 1.5 × spawnInterval 后再读一次 container。(c) 以 `{assetN}` 调用 `SetConfig`，读取 `config` 和 3 个配置资产。(d) 以 `{assetH}` 调用 `SetConfig`，读取 `config`，然后逐波等待，直到 container 有 {capH} 个子物体，最后一波之后 1.5 × spawnInterval 再读一次。通过条件：每一波增加的实例数恰好符合 R4；(a) 的第一波在进入 Play 后 spawnInterval 出现（最多早 1.0 秒或晚 0.8 秒）；(d) 的第一波在调用后 spawnInterval 出现，之后每一波都在上一波之后 spawnInterval 出现（最多短 0.3 秒或长 0.5 秒）；(b) 期间以及 (a)、(d) 的最后一波之后，子物体数不再变化；每次读取的 `config` 都指向当时的当前配置资产（最初是场景里的资产），且 (c) 读到的与第一次读到的是同一个对象；3 个资产仍保持 R2 的数值；不得出现错误或异常日志。
R7. 除这两个脚本外，不要新增或修改任何代码文件（包括编辑器脚本）。
R8. 不要修改 `{prefab}`，不要修改 `{arena}`、`{spawner}` 和 `{container}` 的名称与变换，也不要修改其他任何对象和资产。
R9. 在答案中报告两个脚本的资产路径、3 个配置资产的路径，以及 `{spawner}` 的完整层级路径。
