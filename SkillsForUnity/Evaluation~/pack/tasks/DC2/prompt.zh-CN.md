R1. 在 `{scripts}` 下新建 C# 脚本 `{cls}.cs`，定义 `public class {cls} : MonoBehaviour`，包含：在类内部声明的公开枚举 `DoorState`，成员恰好为 `Closed`、`Opening`、`Open`、`Closing`；可序列化的 float 字段 `travelSeconds`（public 或标记 `[SerializeField]`），在声明处用数值等于 0.5 的字面量初始化（例如 `0.5f`）；公开的 float 成员 `openness` 和公开的 `DoorState` 成员 `state`（各自可以是公开字段，或带 getter 的公开属性）；以及公开无参方法 `void Open()` 与 `void Close()`。工程必须编译通过、没有错误。
R2. Play 模式下的行为：`openness` 始终在 [0, 1] 内（0 为完全关闭，1 为完全打开），进入 Play 模式时门处于 `Closed`、`openness` 为 0。`Open()` 把 `Closed` 或 `Closing` 的门切换为 `Opening`，对 `Opening` 或 `Open` 的门不起作用；`Close()` 把 `Open` 或 `Opening` 的门切换为 `Closing`，对 `Closing` 或 `Closed` 的门不起作用。切换时保留当前 `openness` 并从它继续（进度从不重置），不起作用的调用既不改变运动，也不改变速度。`Opening` 时 `openness` 上升、`Closing` 时下降，速率恒定为每秒缩放游戏时间 1 / `travelSeconds`（每帧 `Time.deltaTime / travelSeconds`），因此完整一次开或关耗时 `travelSeconds`，部分行程按比例更短；`openness` 到达 1 的那一帧状态变为 `Open`，到达 0 的那一帧状态变为 `Closed`。任何时刻最多只有一个运动在进行：切换后只有新方向在推动门。
R3. 门按缩放后的游戏时间运行：`Time.timeScale` 为 0 时，`openness` 和 `state` 都完全不变；`Time.timeScale` 为 0.5 时，门在真实时间里以正常速度的一半运动（按缩放游戏时间计的每秒速度不变）。
R4. 把恰好一个 `{cls}` 组件挂到 `{door}` 上，并在场景中把它的 `travelSeconds` 设为 {travel}（该值存入场景的序列化数据，而不只是代码默认值）。
R5. 验收会进入 Play 模式。`{monitor}` 上的记录器组件（场景搭建的一部分）在每帧末尾（LateUpdate）通过反射读取 `{door}` 上组件的 `openness` 与 `state`，并同时记下 `Time.time`。验收只会调用你的组件的 `Open()` 与 `Close()`，并把 `Time.timeScale` 依次设为 0、0.5，再设回 1。顺序为：从 `Closed` 开始调用 `Open()`，打开途中再次调用 `Open()`；在这次打开过程中，`Time.timeScale` 先为 0 持续约 1 秒真实时间，再为 0.5 持续约 1 秒，然后为 1 直到门处于 `Open`；之后再调用一次 `Open()`，然后 `Close()`，关闭途中再次 `Close()`，关闭途中 `Open()`，打开途中 `Close()`，门处于 `Closed` 后再调用一次 `Close()`。每次读数都必须按记录的游戏时间符合 R2–R3：`openness` 在 [0, 1] 内，且与由上一次读数及其后经过的游戏时间推出的值相差不超过 0.03（一次调用在它前后相邻两次读数之间的某个时刻生效），`Time.timeScale` 为 0 期间完全不变，`state` 符合规定；运行期间不得出现错误或异常日志。
