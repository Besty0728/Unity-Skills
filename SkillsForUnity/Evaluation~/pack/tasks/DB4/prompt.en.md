R1. Under `{scripts}`, create the script `{cls}.cs` declaring `public class {cls} : MonoBehaviour` with four serialized fields (public, or marked [SerializeField]): `Transform target`, `Vector3 offset` (whose default value in the code is {defaultOffset}, written as a `new Vector3(x, y, z)` field initializer with number literals), `bool smoothing` (whose default value in the code is true) and `float smoothSpeed` (whose default value in the code is {defaultSpeed}). The script must compile without errors.
R2. The component does its work in its `LateUpdate()` method (not in `Update` or `FixedUpdate`), once per frame: it computes the point `target.position + offset`, where `offset` is a world-space vector added as is (not rotated or scaled with `target`). When `smoothing` is false it sets the world position (`transform.position`) of the GameObject it sits on exactly to that point; when `smoothing` is true it instead moves that world position toward the point with `Vector3.Lerp(current position, point, smoothSpeed * Time.deltaTime)`.
R3. Attach exactly one `{cls}` component to the camera object `{cam}`, and in the scene set its `target` to the Transform of `{rover}`, its `offset` to {offset} and its `smoothing` to false (these values must be stored in the scene, not only as code defaults).
R4. Do not attach `{cls}` to any other object, do not modify any object other than `{cam}` (`{rover}` and `{other}` included), and add no code file other than this script (editor scripts included).
R5. When the scene runs in Play Mode no error or exception may be logged, and the camera follows as described above with smoothing off: from the first frames on, and again from the next frame after `{rover}` is moved while the game runs (for example teleported to another position by another script or tool), the world position of `{cam}` equals the world position of `{rover}` plus {offset}, within 0.001 on each axis.
R6. In the answer, report the asset path of the script, the instanceId of the object carrying the component and the instanceId of the object its `target` field references in the scene (on Unity 6000.4 and later, where instanceId reads 0, give the entityIds).
