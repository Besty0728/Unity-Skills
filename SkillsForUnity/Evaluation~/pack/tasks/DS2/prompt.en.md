R1. Under `{scripts}`, create the C# script `{cls}.cs` defining the MonoBehaviour class `{cls}` with five public serialized fields: `door` (Transform), `openOffset` (Vector3, local offset from the door's initial local position), `speed` (float, local units per second), `enterCount` (int, default 0) and `exitCount` (int, default 0). The script must compile.
R2. Behaviour: when Play Mode starts, record the initial `localPosition` of `door` as `closedPos`; the open position is `closedPos + openOffset`. Respond only to trigger colliders whose tag is `Player` (ignore objects with other tags such as `{visitor}`): each time a `Player` enters the trigger zone, increment `enterCount` by 1; each time a `Player` leaves the trigger zone, increment `exitCount` by 1. While a `Player` is inside the trigger zone, move `door.localPosition` towards `closedPos + openOffset` at the constant rate `speed` (`Vector3.MoveTowards`) each frame; when no `Player` is inside the trigger zone, move `door.localPosition` back towards `closedPos` at the constant rate `speed` each frame. Repeated entries and exits must work the same way.
R3. Attach `{cls}` to `{zone}` (the only such component in the scene) and set, in the scene: `door` = the Transform of `{door}`, `openOffset` = ({ox}, {oy}, {oz}), `speed` = {speed}.
R4. Configure the trigger physics so that trigger callbacks fire in Play Mode: set `isTrigger = true` on the `BoxCollider` of `{zone}`, and ensure `{player}` has a kinematic `Rigidbody` (`isKinematic = true`, `useGravity = false`).
R5. Verification enters Play Mode and reads the `localPosition` of `{door}` together with `enterCount` and `exitCount` on the component of `{zone}` at five moments as `{visitor}` crosses the zone and `{player}` enters and leaves the zone twice along its path (each sample is taken at least 0.30 s after the door has settled and at least 0.30 s away from every `Player` trigger entry or exit): at each sample the door's local position must be within 0.15 of the expected local position (`closedPos` when closed, `closedPos + openOffset` when open) and `(enterCount, exitCount)` must match `(0, 0)`, `(1, 0)`, `(1, 1)`, `(2, 1)` and `(2, 2)`; no error or exception may be logged while running.
R6. Apart from creating `{cls}.cs`, do not add, delete or modify any other code file (existing movement scripts and editor scripts included).
R7. Do not modify the names, tags or transforms of `{door}`, `{zone}`, `{player}`, `{visitor}` or the path waypoints, and do not modify the existing movement components or any other object or asset.
R8. In the answer, report the asset path of the new script and the full hierarchy paths of `{zone}`, `{door}` and `{player}`.
