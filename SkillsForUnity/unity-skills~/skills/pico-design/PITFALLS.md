# PICO Unity SDK - Hallucination Pitfalls (v3.4.0)

> Anchored to the PICO official documentation for v3.4.0 (crawled 2026-08-13). This file is the anti-hallucination gate for the pico-design module. It lists old APIs that training memory most often gets wrong, semantic traps, mutual-exclusion constraints, and contradictions within the official docs. Details for each area are in the area docs. **The complete deprecation list is in [VERSIONS.md](./VERSIONS.md), the single source of truth.**

## 1. Deprecated / Renamed API Blacklist (the main source of memory errors)

Check this table before writing code. The left column is common in training corpora but **deprecated or renamed in 3.4.0**.

| Old form from memory | Reality in 3.4.0 | Source |
|---|---|---|

Current eye tracking is `PXR_MotionTracking.StartEyeTracking` / `GetEyeTrackingData` | [PXR_EyeTracking](https://developer-cn.picoxr.com/reference/unity/client-api/PXR_EyeTracking/) |

| `PXR_Input.GetMotionTrackerBattery` / `GetFitnessBandBattery` / `GetFitnessBandConnectState` / `SetSwiftMode`, and other motion-device APIs | Deprecated on PXR_Input in 3.2.0 and moved to `PXR_MotionTracking` in the same version | [v3.2.0](https://developer-cn.picoxr.com/document/updates-unity/release-notes-for-version-320/) |

Enums and structs are in the `pxr` namespace (`PXR_Type.cs`) | [OpenXR plugin](https://developer-cn.picoxr.com/document/unity/support-for-the-unity-openxr-plugin/) |

## 2. Signature and Semantic Traps (the method exists, but AI uses it wrong)

| # | Trap | Source |
|---|---|---|
| 1 | `PXR_MotionTracking` methods return **int** (`TrackingStateCode`: 0 = `PXR_MT_SUCCESS`, -1 = `PXR_MT_FAILURE`, -5 = eye tracking permission denied), not bool. `if (GetEyeTrackingData(...))` does not compile. Check `== 0` | [PXR_MotionTracking](https://developer-cn.picoxr.com/reference/unity/client-api/PXR_MotionTracking/) |
| 2 | `PXR_FoveationRendering.SetFoveationLevel` takes **two** parameters `(FoveationLevel level, bool isETFR)`. `FoveationLevel.None = -1`, not 0. Using 0 to mean "off" silently sets Low | [PXR_FoveationRendering](https://developer-cn.picoxr.com/reference/unity/client-api/PXR_FoveationRendering/) |
| 3 | `PXR_Boundary.SetGuardianSystemDisable(bool value)`: the name and the parameter meaning are **opposite** (docs: true = enable, false = disable). Guessing from the name inverts the boundary switch | [PXR_Boundary](https://developer-cn.picoxr.com/reference/unity/client-api/PXR_Boundary/) |
| 4 | `PXR_System.GetSensorStatus()` returns 0 = null, 1 = 3DoF, **3** = 6DoF (there is no 2). `SetSystemDisplayFrequency` accepts only 72, 90 and 120. 60 and 144 are invalid | [PXR_System](https://developer-cn.picoxr.com/reference/unity/client-api/PXR_System/) |
| 5 | `LeaderboardService.WriteEntry` keeps only the best score by default. A worse new score is **silently dropped**. Overwriting requires `forceUpdate = true` | [Leaderboard](https://developer-cn.picoxr.com/document/unity/leaderboard/) |
| 6 | Body tracker `localLocation` uses a **right-handed coordinate system**. Copying the components directly into a Unity Transform mirrors or misorients the object. Convert with `.ToVector3()` / `.ToQuat()` | [Body trackers](https://developer-cn.picoxr.com/document/unity/object-tracking/) |
| 7 | Non-buffered haptics have **no Stop API**. To stop vibration, call `SendHapticImpulse` again with amplitude and duration both 0. Higher vibration frequency feels **weaker** (50 to 500 Hz), which is counterintuitive | [Haptic feedback](https://developer-cn.picoxr.com/document/unity/haptic-feedback/) |
| 8 | Eye tracking requires `StartEyeTracking` before `GetEyeTrackingData`. **The permission dialog appears on Get**. Only `EyeTrackingMode.PXR_ETM_BOTH` is supported | [Eye tracking](https://developer-cn.picoxr.com/document/unity/eye-tracking/) |
| 9 | `FaceTrackingStopInfo.pause = 0` means **pause**, not "do not pause". The official fast mode-switch flow depends on pause = 0 | [Face tracking](https://developer-cn.picoxr.com/document/unity/face-tracking/) |
| 10 | Delete a spatial anchor in this order: **`UnPersistSpatialAnchorAsync` first, then `DestroyAnchor`**. Reversing the order loses the handle, and the anchor on disk can no longer be found | [Spatial anchors](https://developer-cn.picoxr.com/document/unity/spatial-anchors/) |
| 11 | Anchor handles **become invalid on restart**. Across sessions, store only the UUID and call `QuerySpatialAnchorAsync` to get a new handle. Neither that method nor `UnPersistSpatialAnchorAsync` supports concurrency. Call them serially | [Spatial anchors](https://developer-cn.picoxr.com/document/unity/spatial-anchors/) |
| 12 | `LocateAnchor` is **not real-time** for scene anchors. The pose updates only after another `QuerySceneAnchorAsync`, so calling it every frame returns the old value. (Spatial anchors are real-time) | [Scene calibration](https://developer-cn.picoxr.com/document/unity/scene-capture/) |
| 13 | Check `CoreService.AsyncInitialize()` at two levels: first `m.IsError`, then whether `m.Data` is `Success` **or `AlreadyInitialized`**. Rooms, matchmaking, leaderboards, achievements and challenges also need `CoreService.GameInitialize` | [Platform services](https://developer-cn.picoxr.com/document/unity/initialize-the-platform-services/) |
| 14 | After delivering a consumable, call `IAPService.ConsumePurchase(sku)`. Otherwise `GetViewerPurchases` keeps returning the product and the user cannot buy it again. `GetProductsBySKU` takes at most 20 SKUs per batch | [In-app purchase](https://developer-cn.picoxr.com/document/unity/in-app-purchase/) |
| 15 | The cloud save client has **only one API, `CloudStorageService.StartNewBackup()`** (no read, write, upload or download APIs). The total is at most 100 MiB and only 4 fixed directories are backed up. Putting DLC files there makes the backup fail | [Cloud save](https://developer-cn.picoxr.com/document/unity/cloud-storage/) |
| 16 | `RtcService.InitRtcEngine()` must be called after platform initialization succeeds, or it returns `SdkNotInitialized(-3)`. Call `GetToken` before `JoinRoom`. Only one room can be published at a time (`PublishRoom`) | [RTC](https://developer-cn.picoxr.com/document/unity/rtc/) |
| 17 | When the app goes to the background, `popMessage` pauses and the heartbeat disconnects. All messages during the disconnect are **lost**. Listen to `NetworkService.SetNotification_Game_ConnectionEventCallback` and handle events such as Closed and KickedByRelogin | [Rooms and matchmaking](https://developer-cn.picoxr.com/document/unity/matchmaking/) |

## 3. Configuration and Mutual-Exclusion Constraints (each option is valid alone, but enabling both is wrong)

| # | Constraint | Source |
|---|---|---|
| 1 | **Pick one XR plugin.** With both PICO XR and Unity OpenXR enabled, only PICO XR takes effect. The OpenXR route must enable only OpenXR, and enabling another vendor's plugin stops the app from running | [Project settings](https://developer-cn.picoxr.com/document/unity/complete-project-settings/) |
| 2 | **FFR and ETFR are mutually exclusive** and cannot be switched in one step. First call `SetFoveationLevel(FoveationLevel.None, current isETFR)` to turn it off, then set the target. An FFR to ETFR switch may fail on the second call and need a third | [ETFR](https://developer-cn.picoxr.com/document/unity/eye-tracked-foveated-rendering/) |
| 3 | Super resolution and sharpening **cannot both be on for the same Eye Buffer** (only super resolution takes effect). Both are mutually exclusive with Subsampling. Super resolution applies only to the Eye Buffer and not to composition layers. On the same composition layer, supersampling, sharpening and super resolution are also one-of | [Super resolution](https://developer-cn.picoxr.com/document/unity/super-resolution/) |
| 4 | **AppSW x Optimize Buffer Discards = screen tearing** (AppSW needs the depth buffer, which discards it). **AppSW x content protection = judder and ghosting**. **Late Latching x composition layers = layer judder**, and Late Latching does not yet support Unity 2022 | [AppSW](https://developer-cn.picoxr.com/document/unity/application-spacewarp/) · [Late Latching](https://developer-cn.picoxr.com/document/unity/late-latching/) |
| 5 | FFR is disabled by default in URP. The Intermediate Texture takes over the Eye Buffer. Disable Post-Processing, HDR and related Renderer Features | [FFR](https://developer-cn.picoxr.com/document/unity/fixed-foveated-rendering/) |
| 6 | In URP, `pipelineAsset.renderScale` disables Max Adaptive Resolution Scale for adaptive resolution (a known official issue). For dynamic resolution, use `XRSettings.renderViewportScale` (0 to 1, no texture reallocation), not `eyeTextureResolutionScale` (reallocates on every change and has no effect above 2.0) | [Adaptive resolution](https://developer-cn.picoxr.com/document/unity/adaptive-resolution/) · [Render viewport scaling](https://developer-cn.picoxr.com/document/unity/render-viewport-scaling/) |
| 7 | Composition layers: performance guidance is at most 4. `PXR_Composition Layer` is capped at 7 per scene. The VR hard cap is 15, and layers beyond it are **not rendered at all**. Each scene allows at most one Equirect layer and one Cylinder layer | [Compositor layer overview](https://developer-cn.picoxr.com/document/unity/compositor-layer-overview/) · [FAQ](https://developer-cn.picoxr.com/document/unity/max-vr-compositor-layers-supported/) |
| 8 | An Underlay does not appear just by dragging it into the scene. It depends on the render target alpha, so the `PXR_UnderlayHole` shader must cut a hole in the Eye Buffer. Under URP, HDR must also be disabled | [Composition layer parameters](https://developer-cn.picoxr.com/document/unity/about-the-pxr-overlay-component/) |
| 9 | Four prerequisites for video see-through: disable all post-processing; under Vulkan with URP or Built-in, also disable HDR; main camera Clear Flags = Solid Color; Background RGBA all 0. `EnableVideoSeeThrough` takes effect with a delay. For precise status, listen to `VstDisplayStatusChanged`. Call it again after app resume | [Video see-through](https://developer-cn.picoxr.com/document/unity/seethrough/) |
| 10 | **Controllers and bare hands cannot be tracked at the same time.** `Hand Tracking Support = Controller And Hands` switches automatically rather than running both. A design with one hand on a controller and one bare-handed will fail | [Hand tracking](https://developer-cn.picoxr.com/document/unity/hand-tracking/) |
| 11 | Full-body motion capture and body-tracker tracking are **mutually exclusive** (they share the Body Tracking checkbox). Once `High Frequency Tracking (60Hz)` is enabled, it **cannot be turned off at runtime** | [Body tracking](https://developer-cn.picoxr.com/document/unity/body-tracking/) |
| 12 | SecureMR: a global tensor cannot bind to an operator directly. Use `CreateTensorReference` inside the pipeline as a placeholder and map it at submission. A glTF tensor must be a global tensor. Operand and result names **contain spaces and are case-sensitive** (for example `"texture ID"`, `"world pose"`). Camel-case bindings fail | [SecureMR](https://developer-cn.picoxr.com/document/unity/securemr-key-concepts/) |
| 13 | SecureMR Readback permission is **session-level**. If any pipeline in a session uses a camera-type operator, even one that never runs, camera permission must already be granted for the whole session | [Readback tensor](https://developer-cn.picoxr.com/document/unity/use-the-readback-tensor/) |

## 4. Build and Project Pitfalls

| # | Pitfall | Source |
|---|---------|--------|
| 1 | Under Unity 2022, **Vulkan with Development Build crashes consistently**. Enabling Minify options also crashes | [Known issues](https://developer-cn.picoxr.com/document/unity/known-issues/) |
| 2 | A Release build stuck on the Loading screen is caused by the Java-side minifyRelease stripping code (not IL2CPP stripping). Add keep rules for `com.psmart.aosoperation.**` and `com.pxr.xrlib.**` in the Custom Proguard File | [FAQ](https://developer-cn.picoxr.com/document/unity/stuck-on-loading-screen-when-running--demo-built-with-release-mode/) |
| 3 | Eight banned package-name prefixes (`com.unity.`, `com.DefaultCompany.`, `com.test.`, `com.vr.`, `com.xr.`, etc.) block publishing. The default Unity template package name also triggers "copyright check failed: illegal signature" | [Package naming](https://developer-cn.picoxr.com/document/unity/naming-conventions-for-app-package-name/) |
| 4 | From device system 5.11.0, **one signature can be associated with at most 50 APKs**. APKs over the limit cannot run | [FAQ](https://developer-cn.picoxr.com/document/unity/number-of-apks-associated-with-a-key-exceeds-limit/) |
| 5 | On PICO 4 Ultra (Android 14) with Target API Level above 32, Unity external storage read/write stops working. `MANAGE_EXTERNAL_STORAGE` cannot be requested with `Permission.RequestUserPermission()`. Either use Target API 32 or below, or have the Java plugin open the system authorization page. The Project Validation error that remains in the second case is expected | [Read/write permission](https://developer-cn.picoxr.com/document/unity/set-up-read-and-write-permission-for-pico-4-ultra/) |
| 6 | Tracking stopping after a system UI pops up or the app loses focus is not a bug. It is the behavior of `Tracked Pose Driver (Input System)` with the new Input System. Enable Run in Background **and** set the Input System Background Behavior to Ignore Focus | [FAQ](https://developer-cn.picoxr.com/document/unity/tracking-is-disabled-on-application-focus-lost/) |
| 7 | Long-press Home Recenter does not work when the XR Origin lacks `PXR_Manager`, or when Tracking Origin Mode is not Device or Floor. This is a scene configuration issue, not a code issue | [FAQ](https://developer-cn.picoxr.com/document/unity/app-recenter-failure/) |
| 8 | Since SDK 3.1.0, only 64-bit is supported: IL2CPP with ARM64 only. `PXR_Manager` must be on **every scene** (including loading scenes). The two metadata entries `pvr.app.type=vr` and `pvr.display.orientation=180` must be added manually | [SETUP.md](./SETUP.md) |
| 9 | Older SDK versions have **no public download entry**. The consumer store requires the latest version, and enterprise users contact enterprise support. The SDK Demo is not distributed with the package. Download it separately from the `Pico-Developer` organization on GitHub | [FAQ](https://developer-cn.picoxr.com/document/unity/where-to-download-an-older-version-of-sdk/) |
| 10 | PICO devices log only INFO by default. To capture DEBUG logs, run `adb shell setprop persist.log.tag V`. After turning on the device log switch, **restart the device**. Logs are in the `logcatch` folder (not logcat) in internal storage | [FAQ](https://developer-cn.picoxr.com/document/unity/how-to-get-debug-logs/) |

## 5. Contradictions and Typos in the Official Docs (do not trust these even verbatim)

| # | Contradiction or typo | Handling | Source |
|---|---|---|---|
| 1 | Face tracking: the v3.4.0 Face Tracking guide still teaches `PXR_MotionTracking.StartFaceTracking` and similar calls, but the same version's API reference marks all of them `(Deprecated)` (both the PXR_System and PXR_MotionTracking sets). The 3.2.0 changelog also lists them as deprecated | The corpus gives no replacement class. You may follow the guide but state the deprecated status. **Do not invent a "new face tracking API"** | [Face tracking](https://developer-cn.picoxr.com/document/unity/face-tracking/) |
| 2 | XRI version conflict: "Create an XR Scene" says XRI 3.x is not yet supported, while "PICO Building Blocks" says 3.1.0+ is built on XRI 3.x | Building Blocks uses XRI 3.x. For a hand-built scene, conservatively use XRI 2.x. XRI 3.x XR Origin has no pre-set left and right controllers | [Building Blocks](https://developer-cn.picoxr.com/document/unity/pico-building-blocks/) |
| 3 | On the official API page, the section heading for `QuerySpatialAnchorObjectsAsync` is truncated to `QuerySpatialAnchorObjectsAsyn` | Use the code signature as the authority. Copying the heading writes a method that does not exist | [PXR_MixedReality](https://developer-cn.picoxr.com/reference/unity/client-api/PXR_MixedReality/) |
| 4 | The 3.2.0 changelog says "`ExtDevBatteryAction` is deprecated, replaced by `ExtDevBatteryAction`". This is a self-replacement typo | From context it should be `ExpandDeviceBatteryAction` | [v3.2.0](https://developer-cn.picoxr.com/document/updates-unity/release-notes-for-version-320/) |
| 5 | The official achievements example names its own MonoBehaviour `AchievementsService` (the same name as an SDK class), and contains wrong class names such as `Achievements.GetProgressByName` and the misspelling `AchievmentsService` | The real SDK class is only `Pico.Platform.AchievementsService`. Rename a same-named script in your example | [Achievements](https://developer-cn.picoxr.com/document/unity/achievements/) |
| 6 | In the official achievements scene tutorial, the leaderboard example `GetEntries(name, 0, 5, ...)` passes pageSize = 0 as the second argument, so it **returns no entries** | The correct signature is `(leaderboardName, pageSize, pageIdx, filter, startAt)`. Pass a positive pageSize | [Leaderboard](https://developer-cn.picoxr.com/document/unity/leaderboard/) |
| 7 | Two SecureMR naming sets coexist (`RenderTextConfiguration` + `FontTypeFace` vs `RenderTextOperatorConfiguration` + `SecureMRFontTypeface`). The operand names for `ArithmeticComposeOperator` are `"operand0"` on one page and `"{0}"` on another | Use the code in the Complete Runnable Example page as the authority | [SecureMR](https://developer-cn.picoxr.com/document/unity/securemr-operators/) |
| 8 | The body-tracking guide and API reference use different enum and type names (`BODY_JOINT_SET_BODY_FULL_START` style vs the API reference naming). The face-tracking guide's explanation of the `PXR_FTM_FACE_LIPS_VIS` mode conflicts with the API enum comment | Use the enum definitions in the API reference | [Body tracking](https://developer-cn.picoxr.com/document/unity/body-tracking/) |
| 9 | The official Building Blocks page writes the Unity component `Tracked Device Graphic Raycaster` as `Tracker Device Graphic Raycast` | The real Unity component name is `Tracked Device Graphic Raycaster` | [Building Blocks](https://developer-cn.picoxr.com/document/unity/pico-building-blocks/) |

## 6. Capability Limits (common AI overpromises)

| # | Limit | Source |
|---|-------|--------|
| 1 | The PICO SDK **supports Android only**. It does not support PC VR app development | [FAQ](https://developer-cn.picoxr.com/document/unity/is-desktop-app-dev-supported/) |
| 2 | The SDK has no built-in full-body avatar IK solution (the official docs point to the third-party Final IK). The official route for scene interaction is the **XR Interaction Toolkit** (or VRTK). There is no "PICO-specific interaction component set" | [FAQ](https://developer-cn.picoxr.com/document/unity/how-to-achieve-user-scene-interaction/) |
| 3 | The PICO store **does not deliver DLC**. Implement it in-app with `AssetFileService.DownloadById/ByName`. Only non-consumable add-ons can link DLC files | [DLC](https://developer-cn.picoxr.com/document/unity/downloadable-content/) |
| 4 | The 257 methods of `PXR_Enterprise` **work only on enterprise devices**, and they require `InitEnterpriseService` then `BindEnterpriseService` before use. Consumer devices (retail PICO 4 and PICO 4 Ultra) cannot use them | [PXR_Enterprise](https://developer-cn.picoxr.com/reference/unity/client-api/PXR_Enterprise/) |
| 5 | The AR Foundation route **does not support Image Tracking**, and versions are tightly bound (SDK 3.0.x requires Unity 2022.3 + ARF 5.1; SDK 3.1.0 requires Unity 6 + ARF 6.0) | [AR Foundation](https://developer-cn.picoxr.com/document/unity/ar-foundation-for-pico-unity-integration-sdk/) |
| 6 | Place spatial anchors within 3 meters of the headset. The maximum recovery radius is 5 meters. Real-time spatial mesh reading covers only about 5 meters around the headset. For a larger area, the app must store the data itself | [Spatial anchors](https://developer-cn.picoxr.com/document/unity/spatial-anchors/) · [Spatial mesh](https://developer-cn.picoxr.com/document/unity/spatial-mesh/) |
| 7 | Get the Access Token from the developer platform console (Platform Services > API Test). **There is no runtime C# API that returns it** | [FAQ](https://developer-cn.picoxr.com/document/unity/how-to-get-app-access-token/) |

## Usage

- Before writing any PICO code, check section 1 to confirm you are not using a deprecated API, then check the signature in the matching area doc.
- For version migration (2.x to 3.x, or across 3.x minor versions), read the method-level added/removed tables in [VERSIONS.md](./VERSIONS.md).
- If an API is not in the corpus, tell the user it is "not documented in the official docs" rather than filling it in from memory.
