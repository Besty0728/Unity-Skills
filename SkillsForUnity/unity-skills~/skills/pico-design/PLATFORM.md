# PICO Unity SDK — Platform Services (v3.4.0)

> Anchor: PICO official documentation v3.4.0 (fetched 2026-08-13). Every rule can be verified against the source URLs. This domain is in **condensed mode**: each Service lists only its core signatures and calling patterns; for full parameters and error codes, follow the source URLs.

## When to Load This Document

- Before integrating any `Pico.Platform` service (account, friends, achievements, leaderboards, IAP, DLC, cloud save, room matchmaking, RTC, challenges, highlights), confirm the initialization pattern and prerequisite switches.
- Troubleshooting "the API returns -100011 SDK not initialized / callbacks never fire / permission prompts keep reappearing / the friends list is empty".
- Designing the monetization loop: Add-ons / SKUs / subscriptions / DLC download and fulfillment.
- Designing multiplayer gameplay: matchmaking pools, room lifecycle, in-room message send/receive, reconnection after disconnection.
- Compliance-related work: user entitlement checks (copyright protection), sensitive-word detection, content protection (preventing screenshots and recordings).
- Debugging platform services on a PC without repeatedly building an APK.

## Key Rules

| # | Rule | Source |
|---|---|---|
| 1 | **Platform services support only 64-bit app development**; all platform service interfaces must be called only after initialization succeeds. | [platform-services-overview](https://developer-cn.picoxr.com/document/unity/platform-services-overview/) |
| 2 | Synchronous `CoreService.Initialize()` **throws an exception on failure** and must be wrapped in `try/catch (UnityException e)`; it performs a network request internally and may cause a brief startup stutter. | [initialization](https://developer-cn.picoxr.com/document/unity/initialization/) |
| 3 | Asynchronous `CoreService.AsyncInitialize()` requires **checking two levels**: first `m.IsError`, then `m.Data` must be `PlatformInitializeResult.Success` **or** `AlreadyInitialized`; and subsequent calls **must be written inside the `OnComplete` callback (or after an `await`)**. The official docs explicitly list "writing `UserService.GetLoggedInUser()` alongside `AsyncInitialize().OnComplete(...)`" as a wrong example. | [initialization](https://developer-cn.picoxr.com/document/unity/initialization/) |
| 4 | Game modules (**rooms & matchmaking, leaderboards, achievements, challenges**) additionally require calling `CoreService.GameInitialize`, and presuppose that the **Matchmaking service has been enabled** on the PICO developer platform. Success means the result is `GameInitializeResult.Success`. | [initialization](https://developer-cn.picoxr.com/document/unity/initialization/) · [leaderboards-platform-service-setups](https://developer-cn.picoxr.com/document/unity/leaderboards-platform-service-setups/) |
| 5 | Game modules **must** listen to `NetworkService.SetNotification_Game_ConnectionEventCallback`: `Closed` / `GameLogicError` / `KickedByRelogin` / `KickedByGameServer` all require **re-initialization**; on `Lost`, pause sending requests and show a "reconnecting" prompt; resume only on `Resumed`. In addition, when the app is backgrounded, `popMessage` is paused → heartbeat disconnects → **messages are lost during the disconnection**. | [initialization](https://developer-cn.picoxr.com/document/unity/initialization/) · [matchmaking](https://developer-cn.picoxr.com/document/unity/matchmaking/) |
| 6 | Two ways to write asynchronous interfaces: `Task<T>.OnComplete(handler)` or (from 2.1.4) `await task.Async()` to get a `Message<T>`. **The first step for any response is to check `m.IsError`**, and only then read `m.Data`. | [platform-services-overview](https://developer-cn.picoxr.com/document/unity/platform-services-overview/) |
| 7 | Request user permissions **in one batch**: `UserService.RequestUserPermissions(params string[])`, with inputs from the `Models.Permissions` constants (`UserInfo` / `FriendRelation` / `SportsUserInfo` / `SportsSummaryData` / `RecordHighlight`); requesting them one by one causes repeated prompts. `UserService.GetFriends()` returns data only when **both parties have used the app and both have authorized the friend relationship**. | [accounts-and-friends](https://developer-cn.picoxr.com/document/unity/accounts-and-friends/) |
| 8 | Copyright protection uses `UserService.EntitlementCheck(bool killApp)`: `killApp=true` shows a system dialog and exits; with `false` you **must handle `HasEntitlement` yourself**. Paid apps that do not enable it **cannot pass review**; it requires `targetSdkVersion >= 23` and SDK ≥ 2.1.5. User verification (openID + Access Token via S2S) **cannot replace** the user entitlement check. | [user-entitlement-check](https://developer-cn.picoxr.com/document/unity/user-entitlement-check/) · [accounts-and-friends](https://developer-cn.picoxr.com/document/unity/accounts-and-friends/) |
| 9 | The **API Name** for achievements and leaderboards must exactly match the developer platform configuration, and **achievement and leaderboard services cannot currently be tested in the Unity editor** (use a real device or the PC debugging tool). | [achievements-platform-service-setups](https://developer-cn.picoxr.com/document/unity/achievements-platform-service-setups/) · [leaderboards-platform-service-setups](https://developer-cn.picoxr.com/document/unity/leaderboards-platform-service-setups/) |
| 10 | The parameter order of `LeaderboardService.GetEntries` is **(leaderboardName, pageSize, pageIdx, filter, startAt)**; `pageIdx` starts at 0 and `pageSize` takes values in [0,100]; the `UserIds` and `Unknown` values of `filter` are **invalid types and return no entries**; to query by ID use `GetEntriesByIds`. | [LeaderboardService](https://developer-cn.picoxr.com/reference/unity/client-api/LeaderboardService/) · [leaderboards-parameter-details](https://developer-cn.picoxr.com/document/unity/leaderboards-parameter-details/) |
| 11 | `WriteEntry` **does not force updates by default** (it keeps only the best score); to overwrite, you must explicitly pass `forceUpdate = true`. Each user has only one entry per leaderboard. | [leaderboards-use-cases-and-code-samples](https://developer-cn.picoxr.com/document/unity/leaderboards-use-cases-and-code-samples/) |
| 12 | Achievement types have three corresponding patterns: `Count` uses `AddCount`; `Bitfield` (completion rate) uses `AddFields` (pass a 0/1 bit string such as `"100011"`; **once a bit is unlocked it cannot be changed**); `Simple` can only `Unlock`. Count/Bitfield achievements **unlock automatically** when the target is reached; `Unlock` is used to unlock early. | [achievements-use-cases-and-code-samples](https://developer-cn.picoxr.com/document/unity/achievements-use-cases-and-code-samples/) · [AchievementsService](https://developer-cn.picoxr.com/reference/unity/client-api/AchievementsService/) |
| 13 | IAP: `GetProductsBySKU` takes **at most 20 SKUs per batch**; split larger lists yourself. The argument to `LaunchCheckoutFlow2(Product)` must come from `GetProductsBySKU`. **Do not hardcode the currency unit** (outside mainland China, prices are converted using the user's regional exchange rate). For consumable products, **you must call `ConsumePurchase(sku)`** after server-side fulfillment; otherwise `GetViewerPurchases` keeps returning it and it cannot be repurchased. | [in-app-purchase](https://developer-cn.picoxr.com/document/unity/in-app-purchase/) |
| 14 | Hard availability constraints: in mainland China, "game" apps **cannot use IAP without a game publishing approval number**; **subscriptions are supported only outside mainland China**; **highlights are limited to apps listed in the mainland China store**; **content safety (sensitive-word detection) is available only in mainland China**; **exercise data authorization is in experimental stage** and requires submitting the app ID to be enabled (`GetSummary` is limited to the last 24 hours, `GetDailySummary` to the last 90 days). | [in-app-purchase](https://developer-cn.picoxr.com/document/unity/in-app-purchase/) · [subscription](https://developer-cn.picoxr.com/document/unity/subscription/) · [highlights](https://developer-cn.picoxr.com/document/unity/highlights/) · [content-detection](https://developer-cn.picoxr.com/document/unity/content-detection/) · [exercise-data-authorization](https://developer-cn.picoxr.com/document/unity/exercise-data-authorization/) |
| 15 | DLC: **the PICO store is not responsible for downloads**; downloads must be implemented in-app with `AssetFileService.DownloadById/ByName`; only Add-ons of type **"non-consumable"** can be linked to DLC files; before starting a download, verify `AssetDetails.IapStatus == "entitled"`; files are placed in the app's **OBB directory** and are deleted on uninstall. | [downloadable-content](https://developer-cn.picoxr.com/document/unity/downloadable-content/) |
| 16 | The cloud save client has **only one interface, `CloudStorageService.StartNewBackup()`** (SDK ≥ 2.4.0). Passive backup requires all of the following: cloud save enabled on both the platform and the device, more than 24 hours since the last successful backup, content in the backup directory has changed, and the app is closed; total backup per app **≤ 100 MiB**; only 4 fixed directories (and their subdirectories) are backed up, so **do not put DLC files there**. | [cloud-storage](https://developer-cn.picoxr.com/document/unity/cloud-storage/) |
| 17 | Rooms: the `maxUsers` cap is **100**; when the owner leaves, ownership automatically transfers to the user who has been in the room the longest; **the room is destroyed when everyone leaves**; `Room.DataStore` keys ≤ 32 bytes and values ≤ 64 bytes; `Description` ≤ 128 bytes. A successful match is delivered through the `Notification_Matchmaking_MatchFound` notification, then `RoomService.Join2` enters the room. In-room messages sent through `NetworkService.SendPacket` are **≤ 512 bytes per message and ≤ 1000 sends per second**. | [matchmaking](https://developer-cn.picoxr.com/document/unity/matchmaking/) · [RoomService](https://developer-cn.picoxr.com/reference/unity/client-api/RoomService/) · [NetworkService](https://developer-cn.picoxr.com/reference/unity/client-api/NetworkService/) |
| 18 | The RTC initialization order must not be reversed: **platform SDK initialization must succeed first → then `RtcService.InitRtcEngine()`**; otherwise it returns `RtcEngineInitResult.SdkNotInitialized(-3)`; `GetToken` must be called before `JoinRoom`; **only one room can publish an audio stream at a time** (when switching rooms, call `UnPublishRoom` before `PublishRoom`); after leaving a room, `DestroyRoom` is still needed to fully release resources. | [rtc](https://developer-cn.picoxr.com/document/unity/rtc/) · [RtcService](https://developer-cn.picoxr.com/reference/unity/client-api/RtcService/) |
| 19 | RTC numeric bounds: volume **0~400** (100 is the original volume); `roomId` is a non-empty string ≤ 128 bytes, allowing only `A-Z a-z 0-9 _ @ -`; custom messages ≤ 64 KB; per-frame information ≤ 255 bytes; ear monitoring is off by default. RTC requires you to **manually add** `RECORD_AUDIO`, `MODIFY_AUDIO_SETTINGS`, `BLUETOOTH` and other permissions to AndroidManifest.xml. | [rtc](https://developer-cn.picoxr.com/document/unity/rtc/) |
| 20 | Highlights have three prerequisites, all required: request `Permissions.RecordHighlight` → enable the service on the developer platform → in Unity, tick "开启高光时刻" (Enable highlights) under `PICO > Platform Settings` (the SDK automatically writes the `use_record_highlight_feature` metadata). **You must call `StartSession()` before screenshots or recordings**; a single recording lasts at most **15 minutes**, after which the system stops it automatically and invokes the `SetOnRecordStopHandler` callback. | [highlights](https://developer-cn.picoxr.com/document/unity/highlights/) |

### Internal Inconsistencies in the Documentation (Verify Before Copying Official Examples)

- **The example parameter order for `LeaderboardService.GetEntries` is self-contradictory**: the *Leaderboards – Use Cases* page writes `GetEntries("...", 5, 0, ...)` (pageSize=5, pageIdx=0, correct), while the same snippet on the *Achievements – Use Cases* page is written `GetEntries("yourLeaderboardName", 0, 5, ...)` (equivalent to pageSize=0), which returns no entries. **Follow the API reference signature.** Sources: [leaderboards-use-cases](https://developer-cn.picoxr.com/document/unity/leaderboards-use-cases-and-code-samples/) vs [achievements-use-cases](https://developer-cn.picoxr.com/document/unity/achievements-use-cases-and-code-samples/)
- **Class and call names in the achievements example are wrong**: the official example names its own MonoBehaviour `AchievementsService` (clashing with the SDK class name), and contains misspellings such as `Achievements.GetProgressByName` and `AchievmentsService.GetDefinitionsByName`. The only correct class name is **`AchievementsService`**, and you should not use it to name your own script. Source: [achievements-use-cases](https://developer-cn.picoxr.com/document/unity/achievements-use-cases-and-code-samples/)
- **The same interface is spelled inconsistently across pages**; follow the API reference in every case: `RtcService` (guide / PC debugging page writes `RTCService`); `ChallengesService` (PC debugging page writes `ChallengeService`); `MatchmakingService.Cancel` (guide writes `MatchmakingCancel2`, PC debugging page writes `Cancel2`); `MatchmakingService.ReportResultsInsecure` (PC debugging page writes `ReportResultInsecure`); `RoomService.SetDescription` (guide writes `RoomService.etDescription`); `RoomService.GetJoinOrCreateNamedRoomOptions` (guide writes `GetCreateNamedRoomOptions`). Sources: [pc-end-debugging-tool](https://developer-cn.picoxr.com/document/unity/pc-end-debugging-tool/) · [matchmaking](https://developer-cn.picoxr.com/document/unity/matchmaking/) vs the individual API reference pages
- **The DLC guide mentions `GetAssetFileDownloadResult()` / `GetAssetFileDownloadCancelResult()`, but the `AssetFileService` member table has neither function**; the member table provides `SetOnDownloadUpdateCallback` (progress/completion status) and the return values of each `Download*`. Follow the API reference. Sources: [downloadable-content](https://developer-cn.picoxr.com/document/unity/downloadable-content/) vs [AssetFileService](https://developer-cn.picoxr.com/reference/unity/client-api/AssetFileService/)
- **Access token validity for account linking**: the concepts table says Access Token 15 days and Refresh Token 30 days, but the example response has `expires_in=5184000` and `refresh_expires_in=15552000` (60 days / 180 days). Use the actual returned values; do not hardcode the day counts. Source: [account-linking](https://developer-cn.picoxr.com/document/unity/account-linking/)
- **Two menu paths for Platform Settings**: the *Highlights* page writes `PICO > Platform Settings`, while the *PC Debugging Tool* page writes `PXR_SDK > Platform Settings`. Follow the menu in the SDK version your project uses (both refer to the same panel: APP ID / User Entitlement Check / enable highlights). Sources: [highlights](https://developer-cn.picoxr.com/document/unity/highlights/) vs [pc-end-debugging-tool](https://developer-cn.picoxr.com/document/unity/pc-end-debugging-tool/)

## Workflow

### A. Platform Service Initialization (Prerequisite for All Platform Services)

1. **Configure the APP ID**: enter the APP ID from the "API 测试" (API test) page of the developer platform into `PICO > Platform Settings` (`Initialize` reads this editor setting when no appId is passed). The "API 测试" label is the developer platform's page title.
2. **Choose one of two initialization methods**:
   ```csharp
   using Pico.Platform;
   using Pico.Platform.Models;

   // Synchronous: throws on failure
   try { CoreService.Initialize(); }
   catch (UnityException e) { Debug.Log($"Init Platform SDK error:{e}"); throw; }

   // Asynchronous: check two levels
   CoreService.AsyncInitialize().OnComplete(m =>
   {
       if (m.IsError) { Debug.Log($"code={m.GetError().Code} message={m.GetError().Message}"); return; }
       if (m.Data != PlatformInitializeResult.Success &&
           m.Data != PlatformInitializeResult.AlreadyInitialized) { return; }
       // Only here is it allowed to call other platform services
   });
   ```
3. **Batch-request permissions**: `UserService.RequestUserPermissions(Permissions.UserInfo, Permissions.FriendRelation)`, then read `AuthorizedPermissions` from the response.
4. **(Optional) Copyright check**: `UserService.EntitlementCheck(true)`, or with `false` handle `HasEntitlement` / `StatusMessage` / `Application.Quit()` yourself.
5. **(Game services) Initialize the game module**: `CoreService.GameInitialize(accessToken)` (the token comes from `UserService.GetAccessToken()`) or the parameterless `CoreService.GameInitialize()`; then `NetworkService.SetNotification_Game_ConnectionEventCallback(OnGameConnectionEvent)` handles the 8 `GameConnectionEvent` values. On exit, call `CoreService.GameUninitialize()`.
6. **Fallback when initialization fails**: the official guidance is to choose one of two options: provide an offline mode, or guide the user to a "reload page" that lets them tap refresh to re-initialize.
   Sources: [initialization](https://developer-cn.picoxr.com/document/unity/initialization/) · [CoreService](https://developer-cn.picoxr.com/reference/unity/client-api/CoreService/)

### B. Leaderboard + Achievement Linkage (Typical Closed Loop for Game Modules)

1. On the developer platform, create the leaderboard: configure the **API Name** (the `leaderboardName` used in code), sort order (higher is better / lower is better), sort field type (score / time / distance / percentage), data write permission (client-writable / server-only), whether to associate a Destination, and whether to enable friend leaderboards and surpass notifications.
2. On the developer platform, create the achievement: configure the **API Name**, achievement type (simple / count / completion rate), write permission, whether it is hidden, and whether to enable unlock notifications (toast + notification center).
3. **Enable the Matchmaking service** → `CoreService.Initialize/AsyncInitialize` → `CoreService.GameInitialize`.
4. Write scores: `LeaderboardService.WriteEntry(name, score, extraData, forceUpdate)`; when a tiebreaker metric is needed, use `WriteEntryWithSupplementaryMetric(name, score, supplementaryMetric, extraData, forceUpdate)`.
5. Read the leaderboard: `GetEntries(name, pageSize, pageIdx, LeaderboardFilterType.None, LeaderboardStartAt.Top)` → iterate `LeaderboardEntryList` and use `item.User.ID` to determine rank.
6. Linked unlock: after reaching the target rank, call `AchievementsService.Unlock(achievementName, null)`; the response `Message<AchievementUpdate>` uses `Data.JustUnlocked` to determine whether it was just unlocked.
   Sources: [leaderboards-platform-service-setups](https://developer-cn.picoxr.com/document/unity/leaderboards-platform-service-setups/) · [achievements-use-cases-and-code-samples](https://developer-cn.picoxr.com/document/unity/achievements-use-cases-and-code-samples/)

### C. IAP + DLC Purchase and Download Loop

1. On the developer platform, under `"变现 > 附加内容"` (Monetization > Add-ons), create an Add-on: set the **SKU** (cannot be changed after creation), type (non-consumable / consumable / subscription), and release channel; add a new version with price, images, and **DLC files** (single file ≤ 4 GB, up to 25 files, and select the minimum compatible build version), then submit for review.
2. Fetch products in-app: `IAPService.GetProductsBySKU(skus)` (≤ 20 per batch) → display `Product.Price` + `Product.Currency` (**do not hardcode the currency**).
3. Launch checkout: `IAPService.LaunchCheckoutFlow2(product)`; to attach an order note, use `LaunchCheckoutFlow3(product, orderComment)`.
4. Query owned items: `IAPService.GetViewerPurchases()`; for subscriptions, additionally query `GetSubscriptionStatus(sku)` and check `EntitlementStatus` (`Valid` / `GracePeriod` / `Pause` / `Expired` / `Cancel`).
5. Consumable fulfillment: after your own server grants the item → `IAPService.ConsumePurchase(sku)`.
6. DLC download: `AssetFileService.GetList()` → check `IapStatus == "entitled"` → `DownloadById/DownloadByName`; for progress use `SetOnDownloadUpdateCallback` (`Transferred` byte count + `CompleteStatus`); to cancel use `DownloadCancelById/ByName`; to check state use `StatusById/StatusByName` (`DownloadStatus` is `downloaded` / `available` / `in-progress`); to delete use `DeleteById/DeleteByName`. If a file is tampered with, the system deletes it automatically and invokes `SetOnDeleteForSafetyCallback`.
7. Testing: developer accounts can test Add-ons that have not been submitted; a real payment method must be bound; use the local minimum payment amount (e.g. 0.1 CNY in mainland China, 0.01 USD in the US); the Add-on configuration page has a `"支付测试"` (payment test) toggle to simulate success or failure.
   Sources: [in-app-purchase](https://developer-cn.picoxr.com/document/unity/in-app-purchase/) · [downloadable-content](https://developer-cn.picoxr.com/document/unity/downloadable-content/) · [subscription](https://developer-cn.picoxr.com/document/unity/subscription/)

### D. Rooms & Matchmaking + RTC Voice

1. Platform side: enable the Matchmaking service → create a matchmaking pool (Key, minimum / recommended / maximum user counts, whether to manage rooms, match quality threshold, match retention time, suggested cooldown) → add custom data (Data Key + type + default value) → add Queries (expression + weight: required = 0, high = 0.55, medium = 0.75, low = 0.9). Three modes: basic matchmaking / advanced matchmaking / browse mode.
2. Code side: initialize the platform + `GameInitialize` → `MatchmakingService.Enqueue2(pool, options)` or `CreateAndEnqueueRoom2` → receive the match via `SetMatchFoundNotificationCallback` → `RoomService.Join2(roomId, options)`. To give up matchmaking, use `MatchmakingService.Cancel()`.
3. Room management: `CreateAndJoinPrivate2(policy, maxUsers, roomOptions)`, `JoinOrCreateNamedRoom(...)`, `UpdateDataStore`, `UpdateMembershipLockStatus`, `UpdateOwner`, `KickUser`, `Leave`; room events use a set of callbacks such as `SetUpdateNotificationCallback` / `SetLeaveNotificationCallback` / `SetKickUserNotificationCallback`.
4. RTC: under `Edit > Project Settings > Player > Publishing Settings > Build`, tick `Custom Main Manifest` + `Custom Main Gradle Template`, and add the RTC permissions in `Assets/Plugins/Android/AndroidManifest.xml` → after platform initialization succeeds, call `RtcService.InitRtcEngine()` (the return value must be `RtcEngineInitResult.Success`) → `EnableAudioPropertiesReport(interval)` → `GetToken(roomId, userId, ttl, privileges)` (privileges is `Dictionary<RtcPrivilege, int>`) → `JoinRoom(roomId, userId, token, RtcRoomProfileType.Game, isAutoSubscribeAudio)` (returns 0 on success, -1 invalid parameters / -2 already in a room / -3 engine is null / -4 room creation failed) → `PublishRoom` to speak → `LeaveRoom` → `DestroyRoom`.
   Sources: [matchmaking](https://developer-cn.picoxr.com/document/unity/matchmaking/) · [rtc](https://developer-cn.picoxr.com/document/unity/rtc/)

### E. Social Interaction: Presence Invitations and Launch Parameter Parsing

1. Platform side: create a **Destination**: configure the API Name, Deeplink Message (JSON), whether DeepLink is enabled, and the visibility scope; also upload the app package (accepting an invitation launches the app by package name).
2. Set location: `PresenceService.Set(options)`, where `PresenceOptions` uses `SetDestinationApiName` / `SetIsJoinable` / `SetLobbySessionId` / `SetMatchSessionId` / `SetExtra`; **call `PresenceService.Clear()` when leaving a room or exiting the app**.
3. Sending invitations: system panel `PresenceService.LaunchInvitePanel()` / `RoomService.LaunchInvitableUserFlow(roomId)` / `ChallengesService.LaunchInvitableUserFlow(challengeID)`; custom panel `PresenceService.SendInvites(userIds)` / `RoomService.InviteUser(roomId, inviteToken)` / `ChallengesService.Invite(challengeID, userIds)` (`inviteToken` comes from `User.InviteToken` returned by `RoomService.GetInvitableUsers2`).
4. Receiving invitations: `PresenceService.SetJoinIntentReceivedNotificationCallback` provides a `PresenceJoinIntent` (`DestinationApiName` / `MatchSessionId` / `LobbySessionId` / `DeeplinkMessage`); for room invitations use `RoomService.SetRoomInviteAcceptedNotificationCallback` (callback `Message<string>`, the content is the roomId).
5. Launch parameters: for a **cold start**, call `ApplicationService.GetLaunchDetails()` directly; for a **hot start**, first subscribe to `ApplicationService.SetLaunchIntentChangedCallback` and then call `GetLaunchDetails()`, branching on `LaunchDetails.LaunchType` (`Normal` / `RoomInvite` / `Deeplink` / `ChallengeInvite`). Handle both.
6. App navigation: `ApplicationService.LaunchApp(packageName, options)` / `LaunchAppByAppId(appId, options)`; **you must pass `ApplicationOptions` and call `SetDeeplinkMessage(...)`**; to open the store, use `LaunchStore()` (optionally first compare `CurrentCode < LatestCode` via `GetVersion()`).
   Sources: [social-interaction-use-cases](https://developer-cn.picoxr.com/document/unity/social-interaction-use-cases/) · [social-interaction-key-concepts](https://developer-cn.picoxr.com/document/unity/social-interaction-key-concepts/)

### F. Editor-Side Switches: Content Protection and PC-Side Debugging

1. **Content protection** (makes screenshot / recording / casting output black): in the scene, select **`XR Origin`** → `Add Component` → add **`PXR_Manager`** → tick **`Use Content Protect`**. Known issue: **enabling it together with Application Space Warp (AppSW) causes image jitter and ghosting**.
2. **PC-side debugging** (Windows only): on the developer platform's "API 测试" (API test) page, tick the permissions as needed and obtain an Access Token → in Unity, configure `PICO > PC Debug Settings` with `Region` (`Cn` / `I18n`) and the Access Token (written to `Assets/Resources/PicoSdkPCConfig.json`) → open the corresponding demo scene and click Run. Five service categories are supported: accounts & friends, voice chat, social interaction, multiplayer games, and IAP; **all Notification-related features are unavailable**, and **all IAP interfaces are simulated** (the data is not real). After changing the configuration, you must exit the Unity editor and Hub and end all Unity.exe processes in Task Manager for the change to take effect; for repeated debugging in a short period, wait **at least 5 seconds** after closing the debug interface before clicking Run; logs are at `/{project folder}/Logs`.
   Sources: [content-protection](https://developer-cn.picoxr.com/document/unity/content-protection/) · [pc-end-debugging-tool](https://developer-cn.picoxr.com/document/unity/pc-end-debugging-tool/)

## Core API Anchors

Namespaces: `Pico.Platform` (each Service and `Task<T>` / `Message<T>`), `Pico.Platform.Models` (data structures such as `User`, `Product`, `Room`, `Permissions`).

### CoreService — Initialization (Prerequisite for Everything)

```csharp
bool IsInitialized();
string GetAppID(string appId);
void Initialize(string appId);                                  // Synchronous; throws UnityException on failure
Task<PlatformInitializeResult> AsyncInitialize(string appId);   // Asynchronous
Task<GameInitializeResult> GameInitialize(string accessToken);  // Game modules (rooms / matchmaking / network)
Task<GameInitializeResult> GameInitialize();                    // Overload without a token
bool GameUninitialize();
```

### Non-Service Class Routes (Account Linking / Enterprise Services / Server-Side APIs)

- **Account linking (SSO/OIDC) does not use Service classes; it is a web authorization flow**: on the developer platform's "SSO配置" (SSO configuration) page, enter an https redirect domain → send the user to `https://$pico_auth_domain/oauth/authorize?client_key=$app_id&redirect_uri=$url` → on the 302 callback, take the `code` → POST `.../passport/open/access_token/` to exchange for `access_token` + `open_id` → POST `.../passport/open/userinfo/` to get the nickname and avatar → POST `.../passport/open/refresh_token/` to renew. `$pico_auth_domain`: mainland China `openid.picovr.com`, outside mainland China `open-global.picoxr.com`. [account-linking](https://developer-cn.picoxr.com/document/unity/account-linking/)
- **Signing in to Unity Gaming Services (UGS) uses OIDC**: `ApplicationService.GetSystemInfo().IsCnDevice` selects the provider (`oidc-pico-cn` / `oidc-pico-global`) → `UserService.GetIdToken()` → `AuthenticationService.Instance.SignInWithOpenIdConnectAsync(provider, idToken)` / `LinkWithOpenIdConnectAsync(...)`. [accounts-and-friends](https://developer-cn.picoxr.com/document/unity/accounts-and-friends/)
- **Enterprise services** (device information, device control, system configuration, system switches, app management, casting, large spaces) are an independent interface set for PICO enterprise-grade devices, with the class name **`PXR_Enterprise`**. They do not belong to the platform service system and do not require `CoreService` initialization. [enterprise_service](https://developer-cn.picoxr.com/document/unity/enterprise_service/) · [PXR_Enterprise](https://developer-cn.picoxr.com/reference/unity/client-api/PXR_Enterprise/)
- **Server-side APIs have a separate set of docs** (creating/updating achievements and leaderboards, writing user progress, verifying users, querying social relationships, creating challenges, sensitive-word detection, etc.). Entry point: [server-side API reference](https://developer-cn.picoxr.com/reference/unity-server/latest/). Client error code table: [platform-service-client-api-error-codes](https://developer-cn.picoxr.com/reference/unity/client-api/platform-service-client-api-error-codes/) (e.g. `-100011 SDK not initialized`, `-100002 user no login`, `-100007 have no this api permission`).

## DO NOT

| ❌ Wrong | ✅ Correct |
|---|---|
| Writing `UserService.GetLoggedInUser()` **alongside** `AsyncInitialize().OnComplete(...)` | Put all subsequent calls inside the `OnComplete` callback, or after `await task.Async()` |
| Treating asynchronous initialization as successful after only checking `m.IsError` | Also check `m.Data == PlatformInitializeResult.Success \|\| AlreadyInitialized` |
| Calling `CoreService.Initialize()` without try/catch | Synchronous initialization failure **throws an exception**; you must `catch (UnityException e)` |
| Assuming rooms/matchmaking/leaderboards/achievements work right after `Initialize()` | These four categories belong to game modules and also require `CoreService.GameInitialize` (and the Matchmaking service enabled on the platform) |
| Using game modules without listening for network events | `NetworkService.SetNotification_Game_ConnectionEventCallback`, and branch on `GameConnectionEvent` to reconnect or re-initialize |
| Calling `RequestUserPermissions` separately each time a permission is needed | After initialization completes, request all permissions in one batch using `Permissions.*` constants |
| `GetEntries(name, 0, 5, ...)` assumed to mean "page 0, 5 entries" | The signature is `(name, pageSize, pageIdx, filter, startAt)`; write `(name, 5, 0, ...)` |
| Filtering leaderboards by ID with `LeaderboardFilterType.UserIds` | That value is invalid and returns no entries; use `LeaderboardService.GetEntriesByIds` instead |
| `WriteEntry(name, score, null)` assumed to always overwrite the old score | It keeps only the best score by default; pass `forceUpdate: true` to overwrite |
| Calling `AddCount` on a `Simple` achievement, or only calling `Unlock` to record progress on a `Count` achievement | `Count` → `AddCount`, `Bitfield` → `AddFields`, `Simple` → `Unlock`; progress accumulates through Add* and unlocks automatically |
| Naming your own MonoBehaviour `AchievementsService` | Use a different name; `AchievementsService` is the SDK class name (the official example is wrong here) |
| Writing `Achievements.GetProgressByName` / `AchievmentsService.*` / `RTCService.*` / `ChallengeService.*` | Correct class names: `AchievementsService`, `RtcService`, `ChallengesService` |
| Hand-entering a price/currency in `LaunchCheckoutFlow2`, or hardcoding `CNY` in code | Price and currency must come from the `Product` returned by `GetProductsBySKU` |
| Passing 50 SKUs into `GetProductsBySKU` at once | ≤ 20 per batch; split into multiple calls yourself |
| Not calling `ConsumePurchase` after delivering a consumable | You must report fulfillment; otherwise `GetViewerPurchases` keeps returning it and it cannot be repurchased |
| Expecting the PICO store to download DLC for users | The store handles only purchases; downloads must be implemented in-app with `AssetFileService.DownloadById/ByName` |
| Attaching DLC files to a "consumable" Add-on | Only Add-ons of the **non-consumable** type support linking DLC |
| Allowing DLC content to be used without checking `IapStatus` | Check `AssetDetails.IapStatus == "entitled"` to prevent illegal installations from bypassing purchase |
| Putting large DLC files into the cloud save backup directory | The backup total is ≤ 100 MiB; DLC would overflow it and cause backup failure |
| Assuming cloud save has a full set of "upload / download / read / write" APIs | The client has only `CloudStorageService.StartNewBackup()`; everything else is completed passively by the system |
| Calling `RtcService.InitRtcEngine()` before initializing the platform SDK | The reversed order returns `SdkNotInitialized(-3)`; initialize the RTC engine only after the platform SDK succeeds |
| Calling `JoinRoom` without a token, or calling `PublishRoom` in two rooms at once | Call `GetToken` first; call `UnPublishRoom` before speaking in a new room |
| Assuming resources are released right after `LeaveRoom` | `DestroyRoom(roomId)` is still needed to fully release; before the token expires, renew it with `UpdateToken` |
| Relying on the SDK to write RTC permissions automatically | RTC's recording / Bluetooth / network permissions must be **manually** written into `Assets/Plugins/Android/AndroidManifest.xml` |
| Packing more than 512 bytes into a single message, or sending `SendPacket` at high frequency | ≤ 512 bytes per message, ≤ 1000/s |
| Calling `CaptureScreen` / `StartRecord` without `StartSession` | Highlight screenshots and recordings must first call `HighlightService.StartSession()` |
| Handling only the cold-start `GetLaunchDetails()` | Handle both cold start and hot start (`GetLaunchDetails()` after `SetLaunchIntentChangedCallback`) |
| `LaunchApp("com.x.y", null)` | You must pass `ApplicationOptions` and call `SetDeeplinkMessage(...)` |
| Not clearing Presence when a player leaves a room or exits the app | Call `PresenceService.Clear()` promptly; otherwise friends see stale location data |
| Looking for a platform service interface when using the screenshot black-out feature | Content protection is set by ticking `Use Content Protect` on the `PXR_Manager` of `XR Origin` (and do not enable it together with AppSW) |
| Verifying notification callbacks or real payments in the PC debugging tool | All Notifications are unavailable and IAP is simulated; verify on a real device |
